## FASTQ and FASTQC

FASTQ is the file format that NGSs generates, While FASTQC is an computational approach for quality evaluation of your generated data.

Each sequence will contain:

```
sequence ID
sequence
quality ID
quality score # uses ASCII codes of +33 symbols,
              # eg.[worst] some symbols - numbers - capital letters - lowercase letters [best]
```
Phred quality scores quantify sequencing accuracy and are defined as:

$$Q = -10 \log_{10} P(\text{error})$$

where $P(\text{error})$ is the probability that a base is incorrectly called.

### Low quality score? What to do? - Quality Control Considerations for Sequencing Data

When evaluating sequencing data, it is important to first determine whether the data comes from **single-end** or **paired-end** reads, as this can influence downstream analysis and quality assessment.

Sequencing quality is not uniform across reads. In many platforms, **base quality tends to decrease toward the ends of reads** (especially the 3′ end), meaning later bases are often less reliable than earlier ones. A good quality read will be consistent and high-quality along the read and it will be higher than 30. Poor quality reads will have high variance and quality will drastically decrease in length.

Poor quality can indicate issues with **sample preparation**, and re-preparing or re-sequencing the sample may be necessary.

Quality control of the massive FASTQ files can be done by FASTQC [https://www.bioinformatics.babraham.ac.uk/projects/fastqc/]. FastQC provides summaries of:
- Per-base sequence quality
- GC content - Mean mean GC content should be within the expectation at around 45%. 
- Sequence duplication levels
- Adapter contamination

These metrics help identify potential problems before proceeding to downstream analysis.

# Sequence Alignment — Quick Reference Notes

---

## 1. Global Alignment: Needleman-Wunsch

**Goal:** Align two sequences *end-to-end* (every character in both sequences is used).

### Setup

Given two sequences $X$ of length $m$ and $Y$ of length $n$, build a scoring matrix $F$ of size $(m+1) \times (n+1)$.

**Parameters:**

- $s(x_i, y_j)$ — match/mismatch score (e.g. +1 match, −1 mismatch)
- $d$ — gap penalty (e.g. −2)

### Initialization

$$
F(i, 0) = i \cdot d \quad \text{for } 0 \le i \le m
$$

$$
F(0, j) = j \cdot d \quad \text{for } 0 \le j \le n
$$

### Recurrence (Fill)

$$
F(i,j) = \max \begin{cases} F(i-1,\, j-1) + s(x_i,\, y_j) & \text{(diagonal — match/mismatch)} \\ F(i-1,\, j) + d & \text{(up — gap in } Y\text{)} \\ F(i,\, j-1) + d & \text{(left — gap in } X\text{)} \end{cases}
$$

### Traceback

Start at $F(m, n)$ (bottom-right corner) and follow pointers back to $F(0, 0)$.

**Time & Space:** $O(mn)$

---

## 2. Local Alignment: Smith-Waterman

**Goal:** Find the highest-scoring *local* subsequence alignment (best matching region).

### Key Differences from Needleman-Wunsch

| | Needleman-Wunsch | Smith-Waterman |
|---|---|---|
| **Type** | Global | Local |
| **Init** | $F(i,0)=i \cdot d$, $F(0,j)=j \cdot d$ | $F(i,0)=0$, $F(0,j)=0$ |
| **Recurrence** | max of 3 choices | max of 3 choices **and 0** |
| **Traceback start** | Bottom-right $F(m,n)$ | Cell with **highest score** anywhere |
| **Traceback end** | Top-left $F(0,0)$ | First cell with **score = 0** |

### Recurrence

$$
F(i,j) = \max \begin{cases} 0 \\ F(i-1,\, j-1) + s(x_i,\, y_j) \\ F(i-1,\, j) + d \\ F(i,\, j-1) + d \end{cases}
$$

The $0$ floor means: "start a new alignment here if everything else is negative."

**Time & Space:** $O(mn)$

---

## 3. Seed-and-Extend Strategy

Dynamic programming is $O(mn)$ — too slow for aligning millions of reads to a genome. Instead, use **seed-and-extend**:

1. **Seed:** Find short exact matches (seeds/k-mers) between the read and reference.
2. **Extend:** Run local alignment (Smith-Waterman) only around seed locations.

This avoids aligning the full read against the full genome. The key data structures for fast seeding are below.

---

## 4. Suffix Array

A **suffix array** $SA$ for a string $T$ (length $n$) is an array of integers $[0, n]$ that gives the starting positions of all suffixes of $T\$$ sorted in **lexicographic order**.

### Example

For $T = $ `banana$`:

| Suffix | Start Index |
|---|---|
| `$` | 6 |
| `a$` | 5 |
| `ana$` | 3 |
| `anana$` | 1 |
| `banana$` | 0 |
| `na$` | 4 |
| `nana$` | 2 |

$$
SA = [6, 5, 3, 1, 0, 4, 2]
$$

**Searching for pattern $P$:** Binary search on the suffix array → $O(|P| \log n)$.

---

## 5. Burrows-Wheeler Transform (BWT)

### Construction

1. Append `$` to string $T$ (where `$` is lexicographically smallest).
2. Write all **rotations** of $T\$$.
3. **Sort** rotations lexicographically.
4. **BWT** = the **last column** of the sorted rotation matrix.

$$
BWT(T) = \text{last column of sorted rotation matrix}
$$

### Example: $T = $ `banana$`

| Sorted Rotations | Last Col |
|---|---|
| `$banana` | **a** |
| `a$banan` | **n** |
| `ana$ban` | **n** |
| `anana$b` | **b** |
| `banana$` | **$** |
| `na$bana` | **a** |
| `nana$ba` | **a** |



**Key property:** BWT is reversible — you can reconstruct $T$ from BWT alone.

---

## 6. LF Mapping (Last-to-First)

The **LF mapping** connects the **Last column** (L) to the **First column** (F) of the BWT matrix.

### Core Rule

> The $i$-th occurrence of character $c$ in the **Last column** corresponds to the $i$-th occurrence of $c$ in the **First column**.

$$
LF(i) = C(c) + Occ(c, i)
$$

Where:

- $C(c)$ = number of characters in BWT that are lexicographically **smaller** than $c$
- $Occ(c, i)$ = number of occurrences of character $c$ in $L[0..i]$ (the **rank** of $c$ at position $i$)

### Why It Works

- **F column** = sorted characters → all `a`'s are grouped, then all `b`'s, etc.
- Characters with the **same letter** appear in the **same relative order** in both F and L.

### Use

LF mapping lets you "walk backward" through the original string one character at a time, enabling pattern matching without ever reconstructing the full string.

---

## 7. BW Alignment (FM-Index Based Search)

Use BWT + LF mapping to find exact matches of a pattern $P[1..p]$ in $O(p)$ time.

### Algorithm

Maintain a **range** $[top, bot)$ in the suffix array. Start from the **last** character of $P$ and work backward:

```
top = 0
bot = len(BWT)
for i = |P| down to 1:
    c = P[i]
    top = C(c) + Occ(c, top)
    bot = C(c) + Occ(c, bot)
    if top >= bot:
        → no match, stop
```

If $top < bot$ at the end, the pattern occurs $(bot - top)$ times, and positions are $SA[top], SA[top+1], \ldots, SA[bot-1]$.

### Allowing Mismatches

For **approximate** matching, at each step you can **branch** and try all possible characters (not just $P[i]$), tracking a mismatch counter. This is a depth-first/backtracking search over the BWT.

**Time (exact):** $O(|P|)$ — independent of genome size.

## 8. Alignment Output Formats

### 8.1 SAM (Sequence Alignment/Map)

A **tab-delimited text** format for storing read alignments to a reference.

**Header lines** start with `@`:

- `@HD` — file metadata (version, sort order)
- `@SQ` — reference sequence names and lengths
- `@RG` — read group info

**Each alignment line has 11 mandatory fields:**

| Col | Field | Description |
|---|---|---|
| 1 | QNAME | Read/query name |
| 2 | FLAG | Bitwise flag (mapped? reversed? paired?) |
| 3 | RNAME | Reference sequence name (chromosome) |
| 4 | POS | 1-based leftmost mapping position |
| 5 | MAPQ | Mapping quality $= -10 \log_{10} P(\text{wrong})$ |
| 6 | CIGAR | Alignment encoding (e.g. `30M2I18M`) |
| 7 | RNEXT | Mate reference name |
| 8 | PNEXT | Mate position |
| 9 | TLEN | Template/insert length |
| 10 | SEQ | Read sequence |
| 11 | QUAL | Per-base quality (Phred+33 ASCII) |

**CIGAR string codes:**

- `M` — alignment match (match or mismatch)
- `I` — insertion to reference (base in read, not in ref)
- `D` — deletion from reference (base in ref, not in read)
- `S` — soft clip (bases present in SEQ but not aligned)
- `H` — hard clip (bases not in SEQ)
- `N` — skipped region (e.g. intron in RNA-seq)

**Example:** `50M2D20M` → 50 bases align, 2-base deletion, then 20 more bases align.

### 8.2 BAM (Binary Alignment/Map)

BAM is the **compressed binary version** of SAM (not BED).

- Same information as SAM, stored in **BGZF-compressed** binary format.
- Much smaller file size, faster to process.
- Requires an **index** (`.bai` file) for random access.
- Tools: `samtools view` converts between SAM ↔ BAM.

$$
\text{SAM (human-readable)} \xrightarrow{\text{samtools view -bS}} \text{BAM (binary, compressed)}
$$

### 8.3 BED (Browser Extensible Data)

BED is a **separate format** for describing genomic **regions/intervals** (not alignments directly).

| Col | Field | Example |
|---|---|---|
| 1 | chrom | `chr1` |
| 2 | chromStart | `1000` (0-based) |
| 3 | chromEnd | `5000` (exclusive) |
| 4+ | optional | name, score, strand, … |

**Key distinction:** SAM/BAM store full alignment details (CIGAR, quality, sequence). BED just stores **where** something is on the genome.
